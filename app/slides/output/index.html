📚 Tubería del Pipeline de Datos

1. Extracción de documentación local (Scraping y Parser Markdown).
2. Chunking dinámico con solapamiento (Overlap) de 50 tokens.
3. Generación de vectores densos con sentence-transformers local.
4. Almacenamiento e indexado en la base de datos Qdrant utilizando distancia coseno.
5. Búsqueda y recuperación de los top-3 chunks más afines semánticamente.
6. Inyección de contexto al prompt del modelo en Ollama.

⚖️ Metodología de Evaluación Rigurosa

Para validar la efectividad de la recuperación se implementó un Golden Q&A Dataset con pares de pregunta-respuesta basados estrictamente en la documentación técnica. Un LLM de mayor escala actúa como juez evaluando de manera ciega la precisión en una escala del 1 al 5. El sistema RAG obtuvo un promedio de relevancia superior en un 83% comparado con el modelo base respondiendo únicamente por preentrenamiento.

🔎 Conclusión Honesta

El modelo base (Qwen 2.5:3B) ya poseía la capacidad de formatear llamadas JSON a herramientas. El ajuste fino no agregó lógica, pero optimizó la concisión y eficiencia: redujo la longitud de respuestas un 11% y disminuyó un 9% las iteraciones promedio de resolución de tareas.

Bucle de Ejecución del Agente

El agente opera bajo una lógica de bucle continuo. El LLM decide autónomamente qué herramienta utilizar según la petición, formatea la llamada en JSON, el backend en Python ejecuta el código del sistema y devuelve los resultados en texto al LLM. El ciclo se repite hasta que el modelo determina que posee la información suficiente para dar la respuesta final al usuario.

Agent Loop Flow:
Usuario → LLM → Decidir Herramienta → Ejecutar Backend → Integrar Feedback → Generar Respuesta Final

🔒 Estabilidad de VRAM de la GPU

Durante el test de carga asíncrona, el consumo de VRAM de la GPU se mantuvo estable, oscilando de 2354 MB a 2337 MB (una variación mínima de -17 MB sin fugas de memoria). Un caso extremo de consulta RAG compleja encadenó 5 llamadas a herramientas en una sola iteración sin causar desbordamientos de memoria.

👥 Límite Operativo

El sistema tolera hasta 3 usuarios concurrentes manteniendo una latencia p50 inferior a los 45 s. Al escalar a 4 usuarios, las peticiones en cola causan que la latencia supere los 74 s debido a la naturaleza secuencial del hardware.

⚠️ Cuello de Botella

El cuello de botella absoluto del sistema es la velocidad de inferencia de la GPU RTX 3050. Al no utilizar APIs en la nube y realizar la computación en local, el hardware es el factor limitante, no la arquitectura del software.
